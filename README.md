# Atom Studio · Atoms Demo

> 用一句话，生成一个真正能用的 Web 应用。

Atom Studio 是一个 Agent 驱动的应用生成器：输入自然语言需求，Agent 会完成需求拆解、数据建模、界面生成、交互实现与数据持久化，并在浏览器中直接运行生成结果。生成的应用可以继续用自然语言迭代、查看与导出代码、生成公开分享链接。

- 在线体验：https://37jaynrp83joqs3z23w.traesite.cn
- 源码仓库：https://github.com/zhuicaihong/atom-studio-taskflow

## 1. 功能

### 核心主流程

1. **初始化工作区**：首次进入输入称呼即可创建工作区，无需邮箱和密码。
2. **一句话生成应用**：输入需求或选择示例，Agent 展示规划步骤并生成完整应用。
3. **实时预览**：生成结果直接运行在右侧沙箱 iframe 中，可真实点击、输入、拖拽。
4. **继续迭代**：用自然语言修改主题、主色、视图、名称、字段，保留已有数据。
5. **项目管理**：应用自动保存，左侧列表可切换、搜索、删除。
6. **代码可见**：内置引擎生成 `index.html` / `styles.css` / `app.js` / `spec.json`，可查看、复制、下载单文件 HTML。

### 延展能力

- **公开分享**：一键生成 `/p/:slug` 公共访问链接。
- **数据持久化（双层）**：应用数据存 `localStorage`；工作区、项目、对话与生成结果存服务端 JSON 存储。
- **多端适配**：桌面 / 平板 / 手机三种预览尺寸；移动端支持对话与预览切换。
- **多视图运行时**：清单、看板（拖拽）、表格、卡片、周视图、番茄计时六种交互形态。
- **可选大模型**：可接入任意 OpenAI 兼容接口，用真实 LLM 生成单文件应用；默认内置引擎无需 API Key。
- **数据导出**：生成的应用内可导出 JSON 数据备份。

### 内置应用场景

任务 / 看板、习惯打卡、记账、笔记、书签收藏、阅读清单、客户管理、番茄钟；未命中关键词时回退为通用任务管理。

## 2. 实现思路与关键取舍

### 2.1 生成引擎

- **内置引擎（默认）**：把需求解析为 `AppSpec`（应用名称、视图、字段、状态、筛选维度、示例数据、主题等），再由统一的运行时渲染出独立应用。好处是确定性强、零成本、能稳定覆盖常见工具场景。
- **大模型引擎（可选）**：通过服务端转发调用 OpenAI 兼容接口，生成单文件 HTML 应用；密钥只保存在浏览器，服务端仅单次转发、不落盘。
- **取舍**：笔试更看重“可运行、可体验、可扩展”，因此没有把全部资源押注在 LLM 的不确定性上。内置引擎保证任何时候都能演示完整闭环；LLM 作为开放式扩展。

### 2.2 生成的应用如何保证“真能用”

统一运行时提供真实交互能力：

- 新增 / 编辑 / 删除、必填校验、空状态；
- 搜索、状态筛选、分类筛选；
- 看板拖拽换列、清单完成勾选、周视图逐日打卡、番茄钟计时与记录；
- 数据写入 `localStorage`，刷新不丢失；
- 响应式布局与浅色 / 深色主题切换；
- 导出 JSON 备份。

生成结果不是截图或静态模板，而是可直接操作的独立网页。

### 2.3 技术栈

| 层 | 方案 | 说明 |
|---|---|---|
| 前端 | React 18 + TypeScript + Vite | 无 UI 框架依赖，手写设计系统 |
| 后端 | Node.js + Express | 单进程，静态托管 + REST API |
| 存储 | JSON 文件（原子写入） | 单实例演示足够；生产应替换为 Postgres |
| 预览 | iframe + `srcDoc` + sandbox | 生成代码与主应用隔离 |
| 部署 | Node.js 20 FunctionWeb | `PORT` 可配置 |

### 2.4 数据模型

```ts
Project { id, ownerId, name, prompt, engine, spec, files[], messages[], previewHtml, shareSlug, createdAt, updatedAt }
AppSpec { kind, appName, view, fields[], statuses[], seed[], theme, storageKey, features[] }
```

### 2.5 安全边界

- 生成应用运行在带 sandbox 的 iframe 中，主应用状态不暴露给生成代码。
- 分享链接为随机 slug，只暴露只读的应用页面。
- LLM 密钥保存在浏览器 `localStorage`，仅生成时经后端转发一次；服务端不写日志、不持久化。
- 演示版的工作区以浏览器生成的 owner id 识别，不是正式账号体系。

## 3. 本地运行

```bash
npm install
npm run dev        # 前端 5173 + 后端 8787
# 或
npm run build
npm start          # 单进程 http://localhost:8787
```

环境变量：`PORT`（默认 8787）、`DATA_DIR`（默认 `./data`）。

## 4. 目录结构

```
src/
  App.tsx                  应用编排：生成流程、项目、分享
  components/              侧边栏、对话、预览、弹窗
  lib/api.ts               前端 API 客户端与工作区标识
  lib/agent/specs.ts       需求解析、AppSpec 预设、迭代补丁
  lib/agent/templates.ts   生成应用的 HTML/CSS/JS 运行时
  lib/agent/llm.ts         可选大模型生成
server/index.js            API、分享页、LLM 转发、静态托管
```

## 5. 完成度

**已完成**

- 工作区初始化、项目库、对话式生成、步骤可视化
- 8 类内置场景与 6 种视图运行时
- 生成结果的增删改查、搜索筛选、拖拽、计时、本地持久化
- 服务端项目持久化、分享链接、代码查看/复制/下载
- 可选 LLM 引擎与连接测试
- 响应式界面与移动端适配

**未完成 / 已知限制**

- 没有正式账号体系与权限模型（仅浏览器 owner id）
- 服务端存储为单文件 JSON，多实例部署需要替换为数据库
- 内置引擎的语义理解基于关键词与规则，复杂需求仍需 LLM
- LLM 生成的是单文件应用，尚未支持多文件工程与依赖安装
- 分享页与项目数据没有做团队协作、版本回滚

## 6. 如果继续投入

按优先级：

1. **生成质量**：内置引擎接入结构化输出（JSON Schema）与自动修复，降低 LLM 输出失败率。
2. **真实后端生成**：支持生成带 API 与数据库的应用，而非纯前端 localStorage。
3. **账号与协作**：登录、团队空间、项目共享与权限。
4. **版本管理**：每次对话保存快照，可回滚与对比。
5. **模板市场**：社区模板、复制与二次分发。
6. **发布链路**：一键部署生成的应用，形成完整闭环。
